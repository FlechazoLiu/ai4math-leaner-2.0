# Lean 交互式教学与验证平台 (Leaner) - 架构与功能演进设计草案

基于 2026 年 5 月 12 日的产品会议讨论以及当前 `ai4math-leaner-2.0` 的系统代码基础，本项目将从一个“硬核的作业提交系统”转型为**“集成学习、编码、搜索与社区讨论的 Lean 一站式学习平台”**。

以下为整理后的整体平台建构设计与优化方案：

## 一、 核心痛点与现状分析

1. **提交反馈滞后**：目前学生必须提交作业后才能知道 Lean 代码是否报错，且报错直接打回，体验不平滑。
2. **本地环境折磨**：Lean 及 Mathlib 本地安装极其繁琐耗时，初学者很容易在此阶段被劝退。
3. **UI/UX 交互生硬**：
   - 缺少全局“返回”按钮。
   - 导航栏命名偏程序化（如“仪表盘”需优化）。
   - 没有通知提醒（小红点）。
   - Markdown 题目渲染排版过大（如过多使用一级标题）。
4. **孤岛式学习**：学习 Lean 需要查阅大量文档和定理，但目前网站缺乏配套资料聚合与代码提示体系。
5. **算力受限（历史包袱）**：由于 Lean 编译验证极吃算力，之前由于服务器资源不足剥离了 Web Editor，导致在线操作受限。

---

## 二、 全新产品架构与功能设计

### 1. 核心作业与验证流改造 (Interactive Validation)
* **在线实测 (Pre-validation)**：作业提交前，提供“运行验证”按钮。学生在线编写代码时修改一点即可得到实时编译反馈（或手动触发测试），只有在全部通过（或主动选择最终提交）时，才正式录入系统。
* **草稿与多版本库**：支持暂存答案为草稿，以防复杂证明过程丢失。
* **在线 Web IDE 嵌入 (LeanForWeb)**：
  - 在作业题目下方直接嵌入基于 web 的 Lean 代码编辑器。
  - **技术方案**：考虑到服务器算力（之前 50 人并发导致崩溃），可考虑引入轻量化沙盒，或探索基于 WebAssembly 的客户端 Lean 编译方案，以将大部分计算压力转移到学生本地浏览器，服务器仅承担最终打分验证 (`verifier` 节点)。

### 2. 定理搜索与智能提示服务接入 (LeanSearch & LeanStateSearch)
将北大 AI4Math 团队或相关开源的搜索验证工具深度集成入平台：
* **LeanSearch (自然语言查定理)**：平台内嵌搜索框，允许学生用自然语言（如“证明1+1大于2的定理”）直接检索对应的 Lean 定理名。
* **LeanStateSearch (证明状态推荐/In state search)**：结合 Web IDE，实时获取当前的 Proof State（证明状态），通过 AI 或启发式搜索，向学生推荐下一步可能使用的定理策略（Tactic）。

### 3. 资源聚合模块 (Resource Center)
开辟专门的“学习资源”专区，化解从零入门的阻力：
* **社区快速入口**：接入全球 Lean 开发者社区 **Zulip** 链接，引导学生有疑问时查阅。
* **趣味交互集成**：引入或提供 **自然数小游戏 (Natural Number Game)** 等经典入门项目链接，增强趣味性。
* **环境配置与讲义库**：将课程讲义、本地环境配置文档（Linux/Mac/Win）、官方 Docs 集中存放，按课程和周次分类索引。

### 4. 账号系统与社区拓展 (Community)
* **动态讨论区**：学生提交作业后若选择公开，则进入讨论池。允许其他人“评论”、“加星”、“交流不同证法”。
* **角色隔离与体验**：明确“教师”、“助教”、“学生”三种视图。（修复当前系统中助教也能看到自己“交作业”选项的越权 Bug）。

### 5. UI 与交互体验重构 (UI/UX)
* **导航栏升级**：
  - 将“仪表盘”更名为“学习中心”或“我的课程”。
  - 左侧边栏新增“个人中心”、“资源库”固定入口。
* **全局面包屑与返回机制**：顶部或左上角全局增加 `< 返回上一级` 功能，构建完整的页面路径上下文（避免只能退回主页）。
* **通知与动态（小红点）**：
  - 新增 WebSocket 或轮询机制的头部消息按钮（🔔）。
  - 当有“新作业发布”、“评语送达”、“帖子被回复”时，点亮红点（类似微信红点）。

## 三、 技术栈与系统架构演进路线

系统底层已完成 Docker 化前后端分离，接下来的改造点为：

### Frontend (Next.js - `leaner-fe`)
- **布局重构**：修改 `app/dashboard/layout.tsx`，引入具有层级状态（Breadcrumbs）、返回键的现代 App Shell 布局。
- **状态管理**：引入 Zustand 或 React Context 管理“未读消息”、“草稿代码”。
- **Markdown 优化**：在 `components/Markdown.tsx` 中定制化样式（Prose），限制标题字体最大字号，防止排版失控。
- **Web Editor 引入**：集成 Monaco Editor 与 Lean Language Server 适配层。

### Backend (Python/FastAPI - `leaner-be`)
- **消息推送服务**：在 `notification_service.py` 扩充基于用户维度的未读消息计数与推送。
- **搜搜 API 代理**：实现对 LeanSearch/LeanStateSearch 第三方引擎的 API 包装与转发，防止前端直接调用造成的跨域或秘钥泄露。

### Verifier (Lean 验证节点)
- **多容器算力扩展**：修改 `docker-compose` 编排，支持 `verifier` 服务基于队列弹性扩容。
- **异步作业队列**：与直接阻塞 HTTP 请求不同，前端点击“验证”后，后端塞入消息队列（如 Redis/Celery），下发 TaskID 并在前端轮询结果，保证 Web 端不会因编译超时而断开连接。

---

## 四、 实施阶段划分建议

1. **第一阶段 (UI 与核心链路修复)**
   - 导航栏改造、增加返回操作、小红点提醒。
   - 修复通知与 Markdown 渲染排版，剥离助教的写作业权限。
2. **第二阶段 (内容与搜索扩展)**
   - 搭建专门的学习资源板块 (Zulip, 教程, 讲义)。
   - 对接独立的 LeanSearch 嵌入式网页或查询输入框。
3. **第三阶段 (Web 容器级演进)**
   - 攻克 Lean Web IDE 的算力与稳定性难题。
   - 实现实时代码测试（不作为最终提交的多次自检机制）。
   - 接通 Proof State 的下一步提示 (LeanStateSearch) 功能。
